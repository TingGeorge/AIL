# 06: LLM 推薦排序（按類別並行）

**What to build:** 把 05 的成本排序升級成兩個 Agent 的推薦排序。付費選項 Agent 與免費資源 Agent 並行執行，每個 Agent 內部再按類別各打一次 LLM（付費最多 4 條、免費最多 2 條），每條各自逾時、各自失敗。LLM 對它負責的那一組排序整份清單、不刪任何一筆，每筆附一句繁中推薦理由；排在更便宜的項目前面時，理由必須說明原因。

模型只能回傳輸入清單裡的 id：伺服器驗證回傳結果，丟掉不存在的 id、把漏掉的紀錄依成本補回清單尾端。某一類逾時或失敗只讓那一類退回成本排序並在畫面上說明，其他類照常顯示。

先把既有的 OpenAI-compatible client 工廠從需求解析裡抽出來共用（prefactor），再接排序。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] LLM client 工廠抽成共用模組，需求解析與推薦排序都走同一個工廠；需求解析行為不變、既有測試不動就過
- [ ] 每個 (agent, category) 各一次 LLM 呼叫、並行送出，任一組不等其他組
- [ ] 每組 30 秒逾時；逾時或失敗的那一組退回成本排序、`reason` 為 null，事件帶「推薦排序逾時，已改依成本排列」
- [ ] 伺服器驗證模型輸出：不在輸入清單裡的 id 被丟掉、漏掉的紀錄依成本補回，最終筆數等於輸入筆數
- [ ] 結果卡片顯示推薦理由；排在更便宜項目前面的那幾筆，理由說得出原因
- [ ] 兩個 Agent 面板同時在跑，其中一個失敗不會讓另一個的結果消失
- [ ] 排序邏輯的驗證測試不需要真的呼叫 LLM
