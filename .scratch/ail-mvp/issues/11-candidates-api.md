# 11: 候選紀錄查詢 API

**What to build:** 讓候選紀錄可以脫離搜尋結果單獨取得，這樣直接打開一張卡片的網址、或重新整理清單頁，畫面都還在。提供單筆查詢與一次帶多個 id 的批次查詢兩條路徑，兩者與搜尋結果共用同一個資料庫列到畫面物件的轉換函式，不各自轉一次。

詳情頁在這張票要能完整顯示證據：來源 URL、來源類型與權威度、逐欄摘錄、蒐集與確認時間、資料狀態；有 `valid_until` 的顯示「有效至 …」，已過期的顯示「優惠已於 … 到期，僅供參考」；有地址的提供開啟地圖的外部連結（純 URL，不載入地圖 SDK）；沒有 `baseline` 的顯示「無足夠資料計算節省」而不是補一個數字。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 單筆查詢與批次查詢兩條路徑可用，查不到的 id 不會讓整個請求失敗
- [ ] 資料庫列到畫面物件的轉換只有一個函式，搜尋與這兩條路徑都走它
- [ ] 直接打開一張卡片的網址（未經搜尋）能看到完整內容
- [ ] 詳情頁顯示所有 evidence 摘錄；同一個 field 有兩筆摘錄時並列顯示，卡片標為衝突待確認且不在主要排序中
- [ ] 有效期顯示分未過期／已過期兩種文案
- [ ] 有地址時提供地圖連結，沒有地址時不顯示該入口
- [ ] 沒有 baseline 的紀錄明確顯示「無足夠資料計算節省」
