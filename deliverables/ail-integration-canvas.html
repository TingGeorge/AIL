03
VOICE → CONFIRM → SEARCH

使用者主線

  1. 錄音，或直接輸入文字錄音檔送 POST /api/transcribe；文字直接往下一步。
    不支援麥克風時保留原輸入，不插入示範句。
  2. 解析 → 使用者確認POST /api/parse {transcript,current}
    回傳 Need，修改也寫回同一份 schema；未指定保留 null。
  3. 一次篩選，再分組排序POST /api/search {need,exclude,location,costco_ok}
    規格：deterministic gate → paid/free 分類排名。現有版本只有成本排序。
  4. 五類結果 → 證據 → 行動保留每組回傳順序，按規定合併；待確認不混主榜。
    詳情用 candidate id；保存與回報等 Auth 完成後接上。
POST + FETCH STREAM / 不是 EventSource

SSE 要驅動畫面，不是填滿進度条

filter { found, passed, pending,
         groups, excluded_by }
    ↓
{ agent, category, status: "ranking" }
    ↓ 各組完成即推送
{ status: "done", records: [...] }
或 { status: "failed", reason, records }
    ↓
done { pending: [...], excluded: [...] }
現有與目標的差別groups、excluded 已在程式；failed 與真正 LLM 排名還沒完成。建議加 AbortController、requestId、斷線與 partial-result 狀態；只收到 EOF 不應當成完整成功。

Adapter 要保護的邊界

  1. schema 以 shared/need.ts 為準；不能照過時文案送 need.budget。
  2. 合併 need.exclude_tags 與設定的排除，再送頂層 exclude。
  3. target_categories 只強調相關性；仍搜尋五類。
  4. location null 是未定位，不是距離 0。
  5. 這裡的日期是固定示例；正式請求不能把此日期硬編碼。
  6. scope 沒有 mobility/交通時間貨幣化；保留未知，而不是默補「走路」或 0。
輸出也要改 ViewModel，而不是讓 Rec 假扮 Result現有 Result 強制要求 totalCost、servings、distanceKm、walkMin、reliability、dimensions 等值；後端部分欄位是 null 或根本不提供。建議新的 card view-model 明確表達「未知／不適用」，不要用預設 0、99% 或示範維度補齊型別。

06 / BUILD ORDER

先讓一條主線真正通，再擴功能。

依 backend spec 的風險降低順序：先 schema、真資料與搜尋，再 LLM，再帳號。不是先把所有新表和畫面一起做完。

06
契約測試

null ≠ 0、分類完整、未知費用、Costco、tag 未覆蓋、過期/衝突、同源與跨源。

流程測試

語音失敗→文字、取消後重搜、SSE partial/timeout、深連結重載、登入 401、回報失敗。

部署測試

HTTPS 麥克風/定位、代理不緩衝 SSE、API 不進 SW、公開站不用開發者 localhost。

工期不在本次承諾範圍以上是依賴順序與驗收關卡，不是日期／人日估算；未裁決的產品範圍會直接影響工作量。
