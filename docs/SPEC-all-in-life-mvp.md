## 1. 核心概念

ALL in life 不是「幫你找便宜東西的搜尋頁」，而是一局以現金續命的生活生存遊戲。投資人已把大部分資金 ALL IN 市場，留在身上的現金是本局血條；每一次吃飯、移動與採買都會消耗生存天數。

產品的情緒不是賭博刺激，而是帶點黑色幽默的窮酸求生：畫面很帥、數字很殘酷、資料很誠實。玩家可以選擇「最窮酸」或「可以過活」，但系統永遠先守住預算、份量、時間、距離與資格等硬限制。

一句話主張：**錢都在市場裡。今晚，先活下來。**

## 2. 參考風格拆解與轉譯

### FUTUREMODE / BUILDMODE

- 黑色大底、螢光黃綠作單一高能量主色。
- 超大、極粗、緊縮字距的英文標題；描邊字與實心字並置。
- 編號段落、全大寫標籤、細線框與長條資訊結構。
- 科技／未來感來自比例、排版、格線與動態，不依賴大量插畫。

### SITCON Hackathon 2026

- 延續黑＋螢光綠，加入紫色作「重要狀態／下一事件」強調色。
- 首屏同時呈現品牌、即時狀態、倒數與資料面板。
- 表格、頁籤、進度條與時間資訊密度高，但階層仍清楚。

### ALL in life 的轉譯

- 黑底＝資金壓力與深夜交易介面。
- 螢光綠＝可行選項、通過證據閘門、剩餘生命。
- 紫色＝遊戲難度與高風險狀態，不作一般裝飾。
- 黃色＝待確認、Fixture、資料風險。
- 活動倒數改為「現金餘額／任務後餘額／預估生存天數」。
- 活動流程改為雙 Agent 平行搜尋與證據閘門。

## 3. 玩家模型與難度

### 玩家初始狀態（Demo）

- 固定區域：圓山區。
- 初始可用現金：NT$4,200。
- 每日基本燒錢：NT$536（Demo HUD 數值；不是財務建議）。
- 匿名、不使用精確定位。

| 預算 | 等級 | 介面文案 | 排序傾向 |
|---|---|---|---|
| NT$100–200 | 最窮酸 | 只求熱量，不問排場 | 直接費用最低優先 |
| NT$210–400 | 可以過活 | 能吃飽，也保留選擇 | 成本、份量與便利平衡 |
| NT$410–600 | 尚有尊嚴 | 今天不必與錢包互相傷害 | 在硬限制內放寬選擇 |

「窮酸」是遊戲難度，不是對使用者的羞辱。錯誤與空結果文案針對局勢，不攻擊玩家。

## 4. MVP 資訊架構

單頁四幕：

1. **Hero / Survival HUD**：品牌、金句、現金、任務後餘額、生存天數。
2. **Mission Control**：自然語言需求、預算 Slider、人數、難度、梭哈搜尋。
3. **Agent Run**：付費 Agent 與免費 Agent 同時啟動，分別完成。
4. **Loot Table**：食品、日用品、免費／公益、活動、交通五個頁籤；卡片可收藏、開啟證據檔案、前往來源。

不設登入、地圖、導航、營養分數、付款與冗長 Landing Page。

## 5. 主要互動流程

### Flow A：雙人晚餐

1. 玩家看到初始現金與生存估算。
2. 修改需求、拖曳預算、設定 1–6 人。
3. 難度標籤、任務後餘額與生存天數即時更新。
4. 點「梭哈搜尋」。
5. 付費與免費 Agent 同時進入 SCANNING；免費可先完成，表達 partial result 能力。
6. 完成後捲動至結果；預設看到食品成本由低到高。
7. 打開「查看證據」，確認成本、單位、限制、摘錄、來源與資料時間。
8. 收藏可行選項；頁尾顯示收藏數。

### Flow B：免費但有條件

1. 切換「免費／公益」。
2. 卡片以 NT$0 為視覺主角，同時把登記、資格、時段放在卡片前段。
3. 打開證據檔案，確認「免費」只代表直接費用為零。
4. 透過外部按鈕前往官方頁面。

### Flow C：沒有可靠資料

- Fixture 一律用黃色警示，證據抽屜說明它只驗證 UX。
- 沒有來源的結果不得偽裝成「已驗證」。
- 未知運費、庫存、距離或折扣不得推定為零或可用。

## 6. 畫面規格

### Header

- 高度 64px，桌面 sticky。
- Logo 為螢光綠斜切方塊 `A/`＋文字。
- 右側永久顯示「圓山區 · 匿名遊玩」。
- 桌面顯示三個 anchor；手機隱藏以保留寬度。

### Hero / HUD

- 桌面 2 欄：左 1.35fr，右 420px；手機單欄。
- 標題使用 clamp 76–176px，行高 0.72；LIFE 使用描邊字。
- HUD 三格在手機可堆疊；數字使用緊縮字距。

### Mission Control

- 以 10px 螢光綠硬陰影營造遊戲卡匣感。
- 必備欄位：需求、預算、人數。區域與距離由 HUD 顯示。
- 預算範圍 NT$100–600、步進 NT$10。
- 主要 CTA 高 56px、全寬、可鍵盤聚焦。

### Agent Run

- 兩 Agent 桌面並排、手機上下排列。
- 狀態：STANDBY → SCANNING → COMPLETE。
- 掃描中顯示橫向光帶與進度條；一個 Agent 完成時不等待另一個。

### Loot Table 與 Evidence Dialog

- 五類固定命名，不跨類混成單一分數。
- 頁籤可橫向捲動，避免 320px 螢幕擠壓。
- 卡片顯示排名、驗證狀態、提供者、名稱、成本、單位、時間／距離、限制、節省、證據入口、收藏。
- Dialog 顯示證據摘錄、來源層級、查核時間與外部動作。
- 無來源時按鈕 disabled，顯示「等待真實來源串接」。

## 7. 視覺系統

- Canvas：`#0d110d`；Surface：近黑綠 `#131a13`。
- Primary / Survival：`#c9ff36`。
- Secondary / High risk：紫色約 `#7668ff`。
- Warning：`#ffcc40`；Text：`#eef2e8`。
- 介面使用 Geist Sans；數字、狀態、來源使用 Geist Mono。
- 圓角接近 0；主要面板採硬邊框。Mission 與 hover 卡片使用硬陰影。

## 8. 動效與回饋

- 預算、人數、餘額與生存天數即時更新。
- 搜尋演出 0.8–1.4 秒，用於 Demo 節奏，不假裝是真實網路延遲。
- 卡片 hover 上浮 4px並出現螢光硬陰影；觸控不依賴 hover。
- 搜尋完成後捲到結果。
- `prefers-reduced-motion` 下停用掃描與位移動畫。

## 9. 資料誠信與 Demo Fixture

MVP 同時存在兩種資料：

- **已驗證來源**：北美館、臺北市政府、臺北捷運等官方頁面快照；卡片顯示查核日期。
- **Fixture**：僅驗證食品與日用品的卡片、排序與比較介面；以黃色警示且不可作為真實推薦。

上台前必須：

1. 以圓山區真實商家來源取代所有 Fixture。
2. 每筆填入 `collected_at`、`verified_at`、短證據摘錄與 action URL。
3. 每類至少 7 筆通過證據閘門；不足就顯示實際數量與原因。
4. 跑過期、衝突、未知費用與 Agent timeout 測試。

## 10. 實作架構

- Framework：Vinext / React 19 / TypeScript。
- Styling：Tailwind 4＋集中式 CSS tokens。
- UI：Shadcn / Base UI 的 Button、Slider、Tabs、Dialog、Progress。
- State：React local state；不保存精確位置與自然語言輸入。
- Hosting：靜態 export；未使用 D1、R2 或登入。
- WebMCP：`configure_survival_mission` 可設定 budget、people、need，與畫面共用狀態。

## 11. 響應式與可及性

- 320px 起可用；頁籤允許橫向捲動，卡片不產生整頁水平捲動。
- 關鍵按鈕至少約 44px 觸控區；互動有 aria-label。
- Focus 使用 Primary ring；狀態搭配圖示與文字。
- Dialog 可 Escape 關閉並保有焦點管理。
- 外部連結使用 `target=_blank` 與 `rel=noreferrer`。
- 未經同意不讀 GPS；固定區域不是精確位置。

## 13. 60–90 秒 Demo 導演稿

- **0–10 秒**：停在 Hero，指出現金與生存天數。
- **10–25 秒**：拉到 NT$200 進入「最窮酸」，再拉回 NT$300「可以過活」。
- **25–40 秒**：點「梭哈搜尋」，指向兩 Agent 同時掃描，免費 Agent 先完成。
- **40–58 秒**：食品卡片說明 Fixture 黃標，證明不把假資料偽裝成推薦。
- **58–75 秒**：切到免費／公益，打開北美館證據檔案，指出免費時段與資格。
- **75–90 秒**：切交通看捷運官方票價，收尾：「不保證全網最便宜，只保證每個結論回得去來源。」
