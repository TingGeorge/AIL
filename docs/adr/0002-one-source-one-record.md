# 一個來源一筆紀錄，不做跨來源比對

PRD §9.5 與驗收 Case D 原本要求：同一個選項在兩個來源的價格或時間不同時，優先較新且較權威的來源；兩者同等權威而無法判斷時標「衝突待確認」並排除主要排序。

改為：**來源不同就是不同的候選紀錄**。同一家店在官網 260、在外送平台 299，就是兩筆各自 `已驗證` 的紀錄，各自帶自己的 `source_url`、`source_authority` 與 evidence 摘錄，各自進排序、各自被比價，兩張卡片並列給使用者看。匯入者不做跨來源的合併、取捨或權威度排序。

「衝突待確認」保留給**同一個來源自己前後矛盾**的情況（公告標題寫免費、內文寫每人 100 元）。這種紀錄不進主要排序。

## Considered options

- **依權威度取捨（PRD 原案）**：匯入者判斷哪個來源可信，只建一筆。要求匯入者在資料不足時替使用者做判斷，而且被丟掉的那個價格從此不存在 — 使用者若剛好在那個通路買，看到的是錯的。
- **合併成一筆、附價格區間**：卡片顯示「260–299」。無法算總可比成本、無法排序、無法給出一個可執行的外部連結，等於毀掉 FR-08 與 FR-10。
- **一個來源一筆紀錄（採用）**：不判斷、不合併，全部列出，把判斷權交給看得到證據的使用者。

## Consequences

- 使用者看得到同一家店的所有已知價格，包含較貴的那個 — 選項變多，資訊更完整。
- **取捨**：如果兩個來源其中一個是錯的或已下架，錯的那筆仍會被列出來當成可選項。緩解方式是每張卡片都必須帶 `source_url`、`source_authority` 與該欄位的 evidence 摘錄（SPEC-ingestion §5 的必要摘錄不可省），以及 `valid_until` 到期後自動退出主要排序（§7）。系統不宣稱哪一個是對的。
- 資料筆數會變多（同一家店可能三、四筆）；PRD 驗收條件 #5 的「每類 7–10 筆」改以**通過證據閘門的紀錄數**計算，不要求 7–10 個不同商家。
- PRD 驗收 Case D 的期望行為隨之改變：兩個來源不同時不再排除排序，而是兩筆都出現。
