## 怎麼研究與判定

1. 只使用政府、營運機關、商家與提供者第一手公開網頁。搜尋用於找到來源；價格與資格以官方本文／產品欄位核對，不使用二手摘要代替。
2. 在 `data/live` 保存主要來源 URL、逐欄短摘錄、蒐集／確認時間、份量、時間、資格與範圍。每筆一個主要來源；相同品項的不同来源不自動合併。
3. 清楚區分**原文證據**與**衍生計算**。例如食品「兩個單點」是官方單價 × 2，不是原文宣稱的套餐、折扣或多人優惠。
4. 必要費用若未知，必須明填 `null`；不能省略後當成 0。只有價格、必要費用和適用折扣都明確時，才有總可比成本。
5. 來源沒有明示期限就保留 `valid_until: null`，不自訂到期日來假裝官方背書；這也不是永久有效。來源更新、庫存與活動狀態需重新查核。
6. 只有附第一手 URL、實體地址及成對臺灣範圍的来源座標才提升到 DB；無來源不猜地點，直線距離不是實際步行時間。本批未呼叫需 key 的 Google geocoding。
7. 「已驗證／可比較」表示資料欄位有證據、成本可計算且未到明示期限；不保證目前有庫存、名額、開放或符合使用者全部資格。

## 已知不足，不以假資料補滿

- 本批只有有限提供者、有限地理範圍與線上／全臺服務；每類 7 筆是資料涵蓋門檻，不是市場完整度或品質評分。
- 本批沒有精確SKU／份量可比的Costco基準，不能宣稱比Costco便宜。已收錄7筆有來源的團體折扣，但沒有官方公布的優惠碼；沒有碼不等於沒有優惠。
- 食品成分資訊未完整核對。`tags: null` 不代表沒有過敏原；排除條件與未知成分的警告仍須閱讀。
- 人數、時段、日期與資格部分是文字欄位，尚不能完全結構化篩選；不可把單人票價看成全團總價。
- 公益服務資格可能有限，免費不等於任何人無條件可領取。活動與場館開放可能因休館或公告變更。
- 為測試故意製作的過期／矛盾資料放在 `data/食品.json` 及單元測試中，預設不會從公開 API 顯示；不捏造真實商家矛盾案例來湊測試門檻。

## 可重現的匯入與驗證

在 `prototype-v1` 執行，並先設定 server-side `DATABASE_URL`：

```bash
# 離線 schema／來源欄位／涵蓋檢查；不是重新爬網頁
bun run data:validate
# 預設 data/live；全批先驗證，再以一個交易 upsert，不刪舊資料
ALLOW_DEMO_DATA=0 bun run db:import
# 檢查實際 DB 的真實資料；忽略 demo／封存列
bun run data:check
# 產生檔案 SHA-256、來源 URL → 候選 id 與研究快照清冊
bun run data:manifest
# 先啟動 build 的 server，再驗證真實 HTTP／SSE 行為
API_URL=http://127.0.0.1:3000 bun run data:smoke
```

`data:smoke` 是唯讀驗收：五類搜尋、SSE 完整結束、免費總成本為零、來源詳情、數量一致、示範資料 404；不建立帳號或修改資料。

[機器可讀清冊](catalog-manifest.json) 的雜湊只證明檔案內容一致，不證明資料永遠正確。重新研究後應更新 JSON、研究紀錄、清冊並重新匯入；資料過期導致涵蓋門檻不足時應補查真實來源，不能直接延長期限。

**測試隔離：** `bun test` 的 DB 測試會匯入 fixture，只能使用獨立測試資料庫，不要指向實際使用者資料庫。執行與驗收結果見 [整合紀錄](../INTEGRATION.md)。
