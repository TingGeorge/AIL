## 品質與安全要求

- 用官方或實際提供者網頁核對名稱、價格、份量、時間、資格及必要費用；不能只憑搜尋摘要。
- 免費必須有來源明示；未知價格／運費保持 `null`，不能為了通過驗證而填零。
- 不捏造座標、成分、團購碼、Costco 基準或有效期限。非圓山資料標示實際地區；線上商品不宣稱附近門市現貨。
- 有固定日期的活動檢查是否已過期；常設場館也檢查休館／整修公告。
- 通過 schema／證據結構驗證不代表即時有庫存、名額、開放或一定符合使用者資格。
- 保留現有未提交的介面／搜尋功能修改；只增加資料及相關驗證、來源文件與涵蓋說明。

## 加入資料庫的方式

本次使用 `prototype-v1/scripts/import-expansion.ts`，而不是對全部既有資料做 upsert：

```bash
cd prototype-v1
bun run data:validate
# 唯讀試跑；要求各類仍等於基準、100 個新 ID 均不存在。
bun run scripts/import-expansion.ts
# 確認來源與資料後才執行；單一交易、只新增，不更新舊列，不執行 DDL。
bun run scripts/import-expansion.ts --apply
bun run data:check
bun run data:manifest
```

正式執行會先鎖定候選表的寫入、備份完整舊候選列，再新增 100 筆。提交前逐類檢查三倍數量，並比較原 50 列內容完全不變；任何錯誤都回滾。成功後再次執行會因基準不符而停止，不會重複新增。

本機備份與結果保存在 `.scratch/catalog-expansion/`；不含資料庫連線字串或帳號密碼。資料庫整合測試不得指向此使用中資料庫；安全單元測試需清空 `DATABASE_URL`、`TEST_DATABASE_URL` 和供應者 key。
